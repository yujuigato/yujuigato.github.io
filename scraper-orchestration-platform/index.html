Overview

做了什麼

爬蟲原本只能在本機手動執行，沒有排程、沒有隔離環境、也沒有版本紀錄。為此建置了一套自動化平台：

  • 以 Docker 將不同類型的爬蟲（輕量 API 型、需瀏覽器渲染型）分別容器化，各自獨立執行、互不干擾
  • 以 Apache Airflow 建立排程機制，定時自動觸發爬蟲任務，並設定失敗通知
  • 導入 GitLab 做版本控制，取代手動上傳檔案，讓程式碼異動有紀錄可查
  • 整理成標準化的部署流程，供後續維護與環境重建參考
Architecture

Airflow 排程架構

採用 Airflow 標準三件式架構：Scheduler 負責依排程觸發任務、Webserver 提供監控介面、Metadata DB 記錄執行歷史。每個爬蟲對應一個 DAG，以 DockerOperator 啟動獨立容器執行，跑完自動清除，失敗則重試並發送通知。

1

一個爬蟲對應一個 DAG

每支爬蟲獨立定義排程週期，互不影響；新增爬蟲只需新增一個 DAG 檔案，不需改動既有排程。

2

DockerOperator 啟動隔離容器

DAG 觸發時才啟動對應的爬蟲容器，任務結束即自動清除，平時不佔用資源，也避免任務之間互相汙染執行環境。

3

失敗重試與通知

任務失敗會依設定自動重試，仍失敗則發送通知，取代過去「要等人發現資料沒更新才知道爬蟲掛了」的被動狀態。
